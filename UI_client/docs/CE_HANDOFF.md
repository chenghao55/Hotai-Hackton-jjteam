# C＋E 雙人組交接與開工文件

## 角色界線

### C：產品工程與串接

- 接收 D 的操作流程、A 的模型結果、B 的信心門檻、E 的驗收條件。
- 完成手機拍攝端、桌機覆核端、Mock／正式 API 切換、例外畫面與 Demo 版本。
- 交付可操作網址、API 串接說明、操作錄影素材及已知限制。

### E：PM、整合與證據

- 接收 A／B 的 AI 成效與限制、C 的功能版本、D 的使用者測試結果。
- 維護功能範圍、負責人、期限、阻塞、驗收紀錄與效益公式。
- 最後一週才進行 15 頁簡報、3 分鐘影片及投稿整合；前期只保存證據，不做正式排版。

E 不負責判讀照片是否異常；E 負責驗證系統是否依既定結果做出正確分流。

## API 契約

`POST /api/analyze`，使用 `multipart/form-data`：

- `stage`: `pickup | return`
- `current_images`: 本次照片
- `baseline_images`: 借車前照片，可選
- `scenario`: 僅限 Prototype，值為 `blur | normal | damage | dirty`

核心回傳：

```json
{
  "case_id": "CASE-1044",
  "capture_quality": { "passed": true, "issues": [] },
  "vehicle_change": {
    "detected": true,
    "findings": ["右後保桿出現新增刮痕候選區域"]
  },
  "cleanliness": { "level": "normal", "findings": [] },
  "risk_level": "high",
  "confidence": 0.78,
  "recommended_action": "human_review"
}
```

案件狀態：`待分析 → AI完成 → 待人工覆核 → 待清潔／待維修 → 已結案`。
