# 功能驗收與證據表

## 統一完成定義

每個 Issue 必須同時符合：功能可操作、成功測試通過、至少一個例外測試通過、留下截圖或錄影、E 驗收通過。

## Given／When／Then

### 照片品質不合格

- Given：照片模糊或角度錯誤。
- When：使用者送出照片。
- Then：顯示具體原因並要求補拍，不建立車損結論。

### 高信心正常

- Given：照片品質合格，未發現差異或髒污。
- When：AI 完成分析。
- Then：顯示檢查完成，建議動作為 `pass`。

### 疑似新增車損

- Given：借還影像對位後出現新增差異候選區。
- When：AI 回傳 `human_review`。
- Then：使用者端顯示已回報，營運端進入待人工覆核；不得顯示已確定責任。

### 車內髒污

- Given：車內整潔為 `dirty`。
- When：AI 完成分析。
- Then：營運端標示高風險，且可建立清潔任務。

## 小功能測試

| 功能 | 成功情境 | 例外情境 | 證據 |
|---|---|---|---|
| 拍照／選檔 | 圖片可預覽 | 非圖片與超過 12 MB 有提示 | 手機錄影＋元件測試 |
| AI 分析 | 四種結果正確顯示 | API 失敗時保留照片並可重試 | API 紀錄＋畫面截圖 |
| 低信心分流 | 進入人工覆核 | 不顯示為確定車損 | 結果頁截圖 |
| 案件篩選 | 高、中、低風險可篩選 | 無資料顯示空狀態 | 桌機錄影 |
| 人工覆核 | 可改成待覆核或結案 | 非法狀態不更新 | E2E 測試 |
| 派工 | 可建立清潔／維修狀態 | 不產生責任判定 | E2E 測試 |
| 響應式畫面 | 手機與桌機皆可操作 | 窄螢幕按鈕不被遮住 | Playwright 雙裝置測試 |

## 效益假設的驗證方式

- 拍攝通過率＝首次通過照片數／全部首次拍攝數。
- 補拍率＝要求補拍的任務數／全部拍攝任務數。
- 異常召回率＝成功攔截異常數／測試集中全部異常數。
- 誤報率＝被人工判定正常的預警數／全部預警數。
- 人工覆核量＝進入人工佇列的案件數／全部案件數。
- 平均處理時間＝案件從送出到結案的總時間／結案件數。

初賽展示值若尚未完成實測，必須標示為「效益假設」，不得寫成既有成效。
